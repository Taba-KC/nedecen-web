# Principal book workspace

The principal uses `/dashboard/principal?book=grades&page=class-11` as a single workspace. Existing principal routes redirect here. Query parameters identify the book, page and optional view tab, so links, refresh and browser history preserve location. With no selected book, the library opens with an empty contents panel.

`BookWorkspace.tsx` owns navigation, the pin spine, the bookshelf, loading and errors. `WorkspacePage` is the only content surface. It renders a `PageView`: headings, compact summaries, lists, tabs, actions and optional shared workflow widgets. Books do not supply their own page layouts or route components. Descriptions accept inline rich text so summary figures can be bold without changing font size. Introductory labels appear only when explicitly supplied; there is no default workspace label. Class stream guidance is specific to the selected tab; stream assignment is available under Subjects.

The fixed toolbar shows the current book and page. Inside the scroll container, the title, filters beside it, `titleActions` and search stay together in a sticky heading. Each section can declare its own `actions` beside its heading, such as adding a learner beside the class register. Actions live beside the title, section or row they affect. There are no bottom Actions sections or toolbar Actions shortcuts; `PageView` has no top-level `actions` or `links` collections. Account states are plain text labels. Stream names use the shared `streamLabel` display formatter, which uppercases the name and appends STREAM when that word is absent, without changing stored data or edit fields.

Class pages place Edit class and an outlined Delete class action together in the heading. Add learner and its alternative Bulk import learners link sit beside the class register. The same pairing appears in the Learners and Staff books: a filled Add button, the word "or", then an underlined text link. An action's `alternative` supplies the label and destination page for this shared pattern, replacing the bottom import Actions section. Shared contextual actions accept `variant: "outline"` for a transparent button with the book-colored border. Class pages have no bottom Actions section. Class photos, upload handling and the database field are removed by backend migration `0020_remove_class_photos`.

When a page has multiple contextual actions across its heading and sections, buttons default to outlined, including on hover. Explicit `variant: "filled"` takes precedence. Edit class, Rename stream and Edit announcement are filled, with their outlined Delete actions beside them; Add subject and Assign stream are also filled. A page with a single contextual action retains its filled style unless explicitly outlined. Add actions paired with an alternative import link also retain their filled style.

For subpages, the toolbar includes the immediate parent before the current page, for example `Grades & Classes / Grade 11B / Bulk import learners`. The parent is a navigation button. The trail is derived from the book's page tree and works at any depth, while displaying only the nearest parent to keep it compact. Active headings have straight accent lines centered along 75% of their left edges. Active filters use a tinted background and heavier text without an accent line. Two decorative pins use the original filled metallic style, positioned below the header and above the footer.

Learners use first name and surname without a title in registers, account lookup and profiles. Individual learner creation and spreadsheet import omit titles; learner spreadsheet columns are `firstName`, `surname`, `admissionNumber`. Staff still require titles. Backend migration `0019_remove_learner_titles` drops the learner title column and its existing values without removing learners.

Changing a filter retains the mounted page and its previous content until the new view resolves. The retained view is scoped to the same book, page and data revision, so it cannot leak into another page or survive a mutation refresh. Filters remain usable during loading; outdated content is inert until the requested view is ready. Cancelled requests cannot overwrite a newer filter selection. A failed filter request leaves the heading and previous content visible, with an inline retry that reloads the view without reloading the book.

`filterDisplay: "dropdown"` combines a page's filter options into one native select. Staff uses this mode for its five filters, with search beside it in the title row. `searchable: true` keeps search present even when a filter returns a small or empty list. Pages with simple view choices keep filter buttons by default.

To add a feature, add a `BookDefinition` in `books/registry.ts`. Supply its shelf metadata, `load`, `pages` and `view` functions. To add a feature within a book, add a `BookPage` in its page tree and resolve that page into a `PageView`. Stable page IDs identify entities; display numbers come from the current tree. Flattening the tree supplies Previous and Next navigation at any depth.

The open book's `color` also supplies the workspace's `--book-accent`. CSS derives light selection backgrounds, darker text and button fills from it. Contents, tabs, the selected shelf book, page navigation, focus rings and shared workflow buttons inherit this palette. The neutral library uses the default accent. Active headings retain an inset marker and heavier text, so selection is not conveyed by color alone. New books inherit the theme from their registry color without additional styling.

Simple actions use one native dialog with declarative fields and API commands. Imports reuse the roster editor inline on dedicated pages, including editable preview and duplicate skipping. Subject curriculum uses the existing read-only curriculum widget. Requests are scoped to the current book and cancelled logically on navigation so late responses cannot overwrite the destination. A revision reloads the book after a mutation.

Turns use the Web Animations API and temporary inert DOM snapshots without mounting another page component. The animation follows the supplied page-flips GIF: a rolling fold sweeps across the entire sheet, including its toolbar and footer, with a shaded reverse side, faint mirrored content and a moving cast shadow. Forward turns roll right to left; backward turns reveal the incoming page from left to right over the outgoing page. The pins and sidebars remain stationary. Navigation starts immediately and incoming content is copied into the sheet as it becomes ready. Single turns and jumps of up to six decorative sheets finish within 340 ms. The fold is formed with clip paths, gradient strips, transforms and opacity; it does not use a canvas, physics engine or animation dependency. Reduced-motion preferences disable or cancel it. Rapid navigation cancels previous animations and clears their snapshots. Snapshot capture excludes the animation layers to prevent recursive copies and preserves the content viewport's scroll position.

The timetable is excluded. System Streams has an explicit empty state because the backend has no system-stream catalogue. The Curriculum book shows each subject once per grade, only when it belongs to a stream assigned to a class in that grade. Stream memberships are loaded once per distinct assigned stream and indexed by stream and grade; grades without assigned subjects remain visible with assignment guidance. The class subject Curriculum modal uses confirmed lesson concepts for that class allocation to show total concepts, unique concepts taught and coverage, with taught concepts green. Planned lessons, other classes and concepts outside the active shared curriculum do not inflate coverage.

Run `node scripts/test-principal-books.cjs`, `npx tsc --noEmit`, and ESLint for the modified files. The model checks use an in-memory API and do not access or modify school records. The repository production build currently requires access to Google Fonts for the root layout's Geist font.
